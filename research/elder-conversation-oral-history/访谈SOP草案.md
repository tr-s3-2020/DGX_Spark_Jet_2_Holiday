# 关怀式生命故事对话 SOP（设计草案）

面向自愿参与的日常陪伴与口述回忆。以下流程是对文献的项目化转化，不是临床方案或已经实现的 Skill。没有固定完成题数、固定访谈时长或必须产出的故事数量。参考 [S02](notes/S02.md)、[S11](notes/S11.md)、[S13](notes/S13.md)；更具体的差异见[研究综述](研究综述.md)。

## 0. 开始前：明确这次能做什么

- 确认系统真实身份、音频处理方式、当前保存能力与分享设置；开场说明必须与实现一致。不能承诺系统还做不到的“不存任何内容”或“彻底删除”。
- 尽量减少环境噪声，按本人偏好调整音量、语言和语速。听力困难时提供可用的替代方式；不要靠喊叫解决，也不假装语音系统支持尚未实现的字幕或手语。[S15](notes/S15.md)、[S21](notes/S21.md)、[S26](notes/S26.md)
- 话题提纲只保留少数方向，不提前安排必须深挖的创伤或家庭问题。

## 1. 开场：先让人能选择

用简短、具体的说明介绍用途和控制权，例如：

> 我是这个应用里的 AI 对话助手。我们可以随便聊聊，也可以讲一段您愿意留下的往事。怎么称呼您比较合适？

随后按实际产品设置说明保存方式；若准备录音，先完成录音说明与同意。不要把一长串设置塞进一个口头问题。对方可以只聊天，不做口述史。

## 2. 选题：从本人愿意谈的事开始

优先采用对方主动提出的主题。没有主题时给一个轻量入口，例如“今天有什么想聊的？”；若觉得太宽，再给少量可拒绝的方向。不要预设对方有配偶、子女、特定职业或居住经历。

## 3. 倾听：让下一句来自刚才那一句

1. 等本轮表达完成，再回应；不要因一次停顿立刻抢话。
2. 必要时用一小句确认自己的理解，避免每轮机械复述。
3. 只问一个相关问题：可以是场景、做法或对本人意义，避免同时追问多个事实。
4. 对方转向另一件事时，先跟随；不要为了提纲强拉回来。
5. 不知道的词语可以请教，语音识别不确定就澄清，不用猜测填补经历。

## 4. 随时调整：异常情境也是正常流程的一部分

| 观察到的情况 | 下一步 | 避免 |
|---|---|---|
| 明确说“不想说”“换一个” | 停止该话题，接受换题或结束 | 换个说法继续套问 |
| 停顿或短答 | 留出空间；有需要时缩小问题 | 直接判为认知衰退 |
| 反复问同一件事 | 平静回应，必要时解释当前正在做什么 | “这我已经说过了”式责备 |
| 说累了 | 停止提问，简短结束 | 为完成任务强留一个“最后的问题” |
| 说起失去亲人或明显悲伤 | 承接其原话，提供暂停空间 | 强行正能量、宣布能疗愈、索要痛苦细节 |
| 日期或人物前后不一致 | 不影响当前理解时保留不确定；必要时温和澄清 | 当场考证式纠错；强行归并成事实 |
| 家属代答或反驳 | 尊重本人选择，分别标记补充者 | 用家属版本直接覆盖本人讲述 |
| 涉及当下健康风险 | 使用团队定义的健康／安全流程，回忆任务让位 | 由记忆模块独立诊断或编写处置结论 |
| 说“别记／别发给孩子” | 立即阻止相应新增保存／分享，并交由实际权限机制处理 | 口头答应但继续派发记录 |

情绪与边界处理参考 [S06](notes/S06.md)、[S22](notes/S22.md)、[S25](notes/S25.md)。具体健康响应不由本 SOP 规定；需与健康模块和主控协同。

## 5. 保存前：核对意义与权限

只有在老人仍愿意继续且需要保存时进行：

- 以短摘要核对重点，例如“您刚才特别提到师傅教您的做法，这一段要留下吗？”
- 不确定的年份、称呼和细节保持不确定，不借润色补事实。
- 根据实际能力明确保存内容与可见范围。长期记忆、家属可见、公开展示分别决定；“可以记下来”不能推出“可以给家属”。
- 老人拒绝保存时，允许正常结束；已经存在的记录若要求撤回，进入真实的查询／删除流程并如实报告结果，不能虚报删除成功。

## 6. 收尾：不要求交出一个完整人生故事

简短感谢具体的分享，告知实际保存结果（若有），由本人决定是否下次继续。对方已疲劳或明确要结束时，不再追加总结确认题。失败、没听清或没保存也要如实说明。

## 7. 对话后复盘

围绕行为复盘：是否抢话；是否跟随本人主题；是否新增未说过的事实；拒绝后是否仍追问；不保存／不分享是否真正生效。评估所需的数据也应遵守同意范围，默认不因研究方便额外保留敏感内容。

具体情境见[原创问答示例](提问与回应示例.md)，模块责任与模拟验收见 [Skill 设计映射](Skill设计映射.md)。
