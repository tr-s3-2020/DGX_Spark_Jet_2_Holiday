# 从文献到 Skill：当前焦点与团队协同

本文件提出行为和接口需求，**不是现有代码功能说明，也不是已经确定的团队分工**。上下文见 [模块 3 范围梳理](../../docs/module-3-scope.md)。本轮研究没有新增或修改运行中的 `SKILL.md`。

## 全局链路与当前焦点

用户语音 → 语音识别与主对话控制 → 关怀式对话／可选记忆 → 确认与保存 → 在明确许可下用于后续回忆或家属摘要。

健康／安全信号处理横跨链路；语音端负责听清与播报，主控决定当前响应，记忆模块负责资料来源和保存边界。各模块不能同时对老人独立发话。

**模块 3 的当前焦点（v0.5）：**把讲述变成忠实、可限制用途的记忆，以情境子能力支持不同交流需要，并在后台逐步形成可复核年谱。第三项提供方法、时间推理和记忆；最终问法仍由主控统一执行。具体内容见[情境子能力](../../docs/module-3/SCENARIO-SUBSKILLS.md)及[年谱设计](../../docs/module-3/CHRONICLE-DESIGN.md)。

## 需要与其他模块约定的信息

这些是概念字段，不应直接扩展其他成员已冻结的 API。

| 信息 | 为什么需要 | 约定建议 |
|---|---|---|
| 会话／轮次标识 | 让提取结果能够追溯且避免重复处理 | 复用团队 `session_id`、`turn_id` |
| 最终转写状态 | 中间识别结果可能改变，不能当已确认事实 | 与语音侧 `is_final` 对齐 |
| 保存与用途许可 | 听到信息不代表可以长期记住或分享 | 主控持有权威状态；记忆与摘要使用同一判断 |
| 来源 | 区分本人、家属、外部材料 | 在记忆模块内部先提出结构，团队评审后固定 |
| 不确定性与确认状态 | 保留模糊日期、识别疑问及待确认摘要 | 不把模型自信等同于事实准确 |
| 话题边界 | 避免同一会话中被别的模块重新提起禁谈主题 | 区分本轮拒绝与长期偏好，后者也需许可 |
| 风险处置状态 | 防止健康模块与回忆模块同时给不同指令 | 主控统一调度；健康模块返回信号，不让记忆模块替代诊断 |
| 删除／限制访问结果 | 回复需要反映实际执行情况 | 工具成功后确认；失败时不承诺已完成 |

现有健康探针协作文档使用 `session_id / turn_id / text / is_final` 四字段输入；本方案不要求健康模块接收整份人生记忆。家属摘要角色尚需团队确认，不能仅根据名称假定其实现能力。

## 怎么评估“有人情味”

不能只测提取准确率或聊了多久。至少同时观察：

- **选择权：**拒绝、结束、限制用途的要求是否落实。
- **回应质量：**有没有回应刚才的话，是否机械换题、重复夸赞或替人下情绪结论。
- **表达负担：**是否一次多个问题、连续追问、要求精确日期。
- **记忆忠实性：**摘要是否新增事实，来源与不确定性是否保留。
- **主观体验：**在自愿且不增加负担的前提下，询问“有没有哪一句让您不舒服／不想回答”。

[evaluation_cases.json](evaluation_cases.json) 提供 16 个原创模拟情境，覆盖上述行为。它们是人工走查与后续评估的种子，不是已执行的自动化测试，也不能代替长者参与设计。

首轮演示应至少展示：正常讲述、拒绝换题、疲劳结束、含糊时间、不准分享、语音识别不确定。审核者检查**实际工具调用与落库结果**，不能只看模型嘴上答应了什么。

## 后续协同顺序

1. 团队先确认主控、对话策略和记忆模块的责任边界。
2. 使用本库的模拟案例，约定保存、分享与停止的可观察结果。
3. 再据此编写或修改 Skill，接上真实的权限与存储行为。
4. 邀请不同偏好、语言和沟通能力的长者自愿试用，允许随时退出；分别记录对设计的意见，不把少数人的偏好泛化到所有老人。
