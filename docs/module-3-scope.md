## 1. 全局目标

根据任务一、任务二分支，产品方向是 AI 陪伴老人：能自然地听老人说话并回应，在后续对话中延续过去的经历，同时把健康相关信息交给专门模块处理，并供家属摘要使用。

建议首轮验收目标：用一个老人的连续两次会话，演示「能听说 → 能接续过去的话题 → 健康信息按约定处理 → 家属侧获得相应记录」。各模块完成不等于这个完整流程已经跑通。

## 2. 如果第三项是长期记忆，我们交付什么

目标：让对话系统在跨会话时找回老人真实说过的、与当前话题相关的信息，并能追溯来源。

例子：第一次会话中老人说「我以前在铁路上工作」。第二次谈起过去的工作，主系统能取回这条记忆，自然继续话题。没有记录时返回未命中，不编造往事。

核心能力建议分为四项：

1. **记录**：从已结束的发言中保存有价值的信息，关联用户、会话、轮次和来源时间；不把临时 partial 转写或模型猜测当成事实。
2. **保存**：跨会话、重启后仍可使用；用户之间隔离；同一轮重放不会重复写入。
3. **检索**：根据当前话题返回少量相关记忆及来源，明确未命中；避免把所有历史都塞进回复上下文。
4. **更正**：老人纠正旧信息后，旧记录不再作为当前事实返回；允许删除指定记忆。

ASR、TTS、最终回复生成、健康判断和家属日报分别由对应模块承担。长期记忆不把健康信号改写成诊断，也不自动把私人回忆全部推送给家属。

## 3. 现在的 focus

**第一阶段只做可独立验证的文本记忆闭环：写入 → 持久保存 → 新会话检索 → 返回来源。**

建议交付顺序：

1. 确认第三项原始需求，选一份两次会话的固定演示样例。
2. 与主系统约定三个操作：`record_turn`、`retrieve_memories`、`correct_memory`。这些是提案名称，尚未实现，也不是已接受的公共接口。
3. 先用固定样例和简单本地存储验证闭环，再根据检索效果决定是否需要语义模型或向量索引。
4. 提供统一入口、运行说明与样例，让任务一用模拟返回值也能先完成接入。
5. 接入真实对话流程，再测响应延迟、召回质量和错误处理。

首轮检查：跨会话能找回；服务重启后仍能找回；无匹配时不杜撰；用户之间不串数据；重复事件不重复保存；更正后不继续引用旧事实。

## 4. 必须对齐的协作接口

| 对接方 | 我们需要对齐什么 | 接口意义 |
|---|---|---|
| 任务一 / 主系统 | final 文本、`session_id`、`turn_id`，新增稳定 `user_id`、时间与语言信息的归属 | 会话 ID 不能替代用户 ID，否则跨通话记忆无法可靠关联 |
| 普通回复生成方 | 检索发生的时机、返回数量与长度、来源字段、未命中与超时状态 | 生成方才能引用真实记录，并控制语音等待时间 |
| 任务二 / Yunsheng | 用药安全输出优先级；健康信号是否进入记忆及如何标记来源 | 记忆不能覆盖固定安全话术，也不能把结构标签当诊断 |
| 任务四 / 家属侧 | 需要哪些记忆或摘要、可共享范围、读取或推送方式 | 避免重复保存与未经区分地传播完整聊天内容 |
| 集成协调人 | 公共入口、代码目录、依赖环境、DGX 工作目录、端口和资源 | 避免各模块单独能跑、拼起来失败 |

注意：任务二输入严格只接受 `session_id/turn_id/text/is_final`，额外字段会报错。因此全局事件可以有更多字段，但主系统必须为任务二显式适配，不能直接把带 `user_id` 的事件原样传入。

建议的调用关系（待共同确认）：

```text
老人音频 → 任务一得到 final 文本 → 主系统关联身份与轮次
                                  ├─ 任务二：安全与健康输出
                                  │   ├─ 固定安全回复 → 任务一播放
                                  │   └─ 健康信号 → 任务四
                                  ├─ 第三项：查询相关长期记忆
                                  │   └─ 普通回复生成 → 任务一播放
                                  └─ 发言记录 → 第三项异步保存
```

检索可以准备在前，但对外回复仍须遵守安全分流。建议写入不阻塞首句回复；检索超时返回明确状态，由主系统继续不依赖历史事实的对话。具体延迟预算需端到端测量后共同确定。

## 5. 当前需要解决的集成缺口

1. **语言不一致**：任务一最新提交 `d7e8cd0` 改为英文提示、规则与 NVIDIA NeMo 语音后端；任务二文档和样例仍以中文为主。必须先确定首轮演示语言，再统一测试样例，不能假设两者已兼容。
2. **安全处理重复**：任务一已有 P0/P1 规则并直接输出回复，任务二有自己的用药安全门和三种 response mode。需要明确生产调用路径和优先级；接入未验证前不直接删除现有保护。
3. **分级不能直接映射**：任务二的 `low/moderate/high` 不是 P0/P1/P2；相关转换应由负责方明确约定。
4. **失败不能伪装成事实**：任务二文档说明语义失败可能降级为 `none/low`，且无独立降级标志。其他模块不能把它保存成「用户健康正常」的结论。
5. **回复编排尚未统一**：任务一当前在 `_respond` 中直接调用安全判断和 LLM，缺少已接通的任务二与长期记忆调用点；需要与其负责人约定接入口。
6. **运行环境尚未证明统一**：任务一记录部分来自 A800 环境，不能当作 DGX Spark 已验证。任务二也明确 DGX 联调待完成。
