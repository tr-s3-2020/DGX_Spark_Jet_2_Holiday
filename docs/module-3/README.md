## 1. 在整个项目中解决什么问题

项目的整体方向是老人语音陪伴：能听懂、能回应、能接续过去的谈话，并与健康信息处理和家属摘要协作。第三项重点解决其中四个相连的问题：

1. **怎样聊：**提问跟随老人的讲述，尊重其节奏与选择，避免把陪伴变成问卷或事实采集。
2. **怎样记、怎样再使用：**区分本人说过的内容、他人补充和系统推测，保留不确定性，并按许可保存、检索、更正或删除。
3. **怎样越来越了解这个人：**记录每次对话中的情绪反应、交流条件和明确反馈，结合多次会话总结，逐步更新沟通偏好，帮助主控调整问题形式、节奏和话题选择。
4. **怎样逐步成谱：**汇总“几岁时”“几年后”“退休前”等时间线索，在后台推算年份、区间或事件顺序，并保留可追溯的细节与 AI 整理文字。

例如，老人说：“以前跟师傅学修自行车，大概是七十年代。”系统可以顺着“学修车”继续聊；如果允许保存，就保留这段经历及时间的不确定性。下次谈起手艺时，可以取回相关记忆，但不能凭空补出具体年份、师傅姓名或人生评价。

**目前 focus：建立同时支持个人经历与交流适配的长短期记忆流程：记录 → 后台提取与分析 → 发布记忆与偏好 → 实时读取 → 根据新反馈修正。** 后台可提前整理已获准保存的历史，也可在聊天期间并行工作；老人不等分析完成才得到回复。老人选择只聊天、不保存或直接结束，也应是正常结果。

“像老朋友一样记得细节”在这里指记得对方在意的人、事、物和交流习惯，并在相关时自然回应；系统仍明确自己的 AI 身份。个性化程度不能仅用记住多少事实来衡量，还要看这些记忆是否让对方更自在。

## 2. 为什么以口述史和长者沟通为依据

口述史提供访谈、叙事权和资料保存的方法；长者沟通资料帮助我们考虑尊重、表达负担和个体差异。我们用这些方法指导设计，再通过实际交互验证是否适合 AI 场景。

| 设计问题 | 资料依据 | 在本项目中的转化 |
|---|---|---|
| 如何避免机械盘问？ | [Baylor 访谈手册 S07](../../research/elder-conversation-oral-history/notes/S07.md)、[NPS 访谈技巧 S08](../../research/elder-conversation-oral-history/notes/S08.md) | 一次一个问题，沿当前回答追问，允许停顿和换题 |
| 如何表达尊重？ | [中文长者沟通指南 S14](../../research/elder-conversation-oral-history/notes/S14.md) | 使用成人之间的自然语气，询问称呼与交流偏好，避免幼儿化和失实夸赞 |

## 4. 计划怎样做成 Skill

以下是实现方案，尚未成为固定接口或运行行为。

### 记忆架构：两类内容，两个时间层次

根据卢易锋提出的设计方向，数据库需要同时服务于**个人历史记录**和**持续的交流适配**。长短期记忆是功能上的分层；是否使用同一个数据库中的不同表，或拆成独立存储，留到接口与实现阶段决定。

| 内容维度 | 短期记忆：支撑当前和近期交流 | 长期记忆：支持跨会话延续 |
|---|---|---|
| **个人经历与专属细节** | 当前话题、刚提到的人物、尚未讲完的故事、近期关心的事 | 人生经历、重要关系、兴趣、珍视的物件，以及获准保留的生活细节 |
| **情绪反应与交流条件** | 今天说累了、当前环境嘈杂、刚要求放慢、对某个问题的回应及本轮禁谈主题 | 本人明确的交流偏好，或经多次观察形成且仍可修正的偏好判断；保留适用条件和证据 |

**短期记忆强调当前相关性与有效期，长期记忆强调跨会话保留价值。使用频繁不等于只能放短期。** 例如，偏好的称呼可以长期保存，并在每次会话开始时进入短期上下文；多年前的经历也可以因当前话题相关而被临时调入。短期上下文应少量、有选择，避免把整个档案都放进一次对话。

### 两类记录分别怎样组织

**A. 个人经历与细节记录**回答“他讲过什么、什么对他重要”。记录事件或细节、相关人物、时间及其不确定性、原始轮次来源、确认状态和使用范围。其用途既包括逐步形成个人历史，也包括让日常交流有连续性，例如记得对方在种茉莉、惦记一件未完成的小事。

**B. 交流观察与偏好记录**回答“在什么条件下，以什么方式交流，对方如何回应”。建议每条观察保留：

- **条件：**当时的主题、语言／方言、环境、本人表达的疲劳情况；只有实际获得的信息才记录。
- **系统采取的方式：**提问长短、开放或具体问题、回复长度、语速等实际可观测设置。
- **对方的反馈：**明确说出的喜好、情绪与不适，以及可观察的回应；将原话／行为与系统解释分开。
- **证据与范围：**对应会话和轮次、观察时间、仅当次适用还是可能跨会话适用、确认或待验证状态。
- **后续更新：**是否存在反例、最近是否仍适用，以及本人更正、撤回或限制使用的要求。

例如，“今天聊到工作时说‘这件事我不想讲’”是一条有上下文的观察；不能直接升级为“他永远讨厌谈工作”。沉默、短答或聊天变长也不能单独证明难过、不喜欢或开心。明确的本人反馈优先于模型推测；推测保留为可修正的假设，不写成确定情绪、人格或诊断。

### 实时交流与后台分析分别推进

会后先在已允许的记录范围内提取故事与细节、交流观察及明确反馈。后续分析可以提前在两次聊天之间进行，也可以与下一次聊天重叠；不要求等老人再次问起才分析。后台以数据变化为触发点，不在没有新信息时反复调用模型。

1. **会中更新短期状态：**跟踪当前话题、刚提出的要求与当天条件，使主控及时调整。明确停止或换题要求立即生效，不等会后分析。
2. **会后形成有来源的总结：**提取新增经历、近期事项、明确反馈和交流观察；不保留无用途的重复内容，也不从未获准保存的谈话中另存一份偏好摘要。
3. **后台并行整理：**故事与时间线、交流偏好、检索快照是独立任务；需要的来源先提交，再开展依赖它的分析。明确偏好可以使用；推测结合跨会话证据与反例核对，重复次数本身不是确认标准。可用部分分别发布，不等待所有分析结束。
4. **实时有选择地调用：**把已经准备好的相关经历、近期事项及适用偏好装入短期上下文；依据相关性、时效、本人重要性和权限筛选。普通后台更新供下一轮使用，不临时打乱当前回复。
5. **继续修正与遗忘：**新反馈优先更新旧判断；短期状态设置有效期，过时的偏好降为待核实或停止使用。更正和删除需同步到派生摘要与短期上下文，避免旧判断再次出现。

“今天累了”通常只影响当次；“以后请叫我陈老师”在获准后可成为长期偏好。一次对话没有足够新信息时可以不更新。具体保留期限、过期规则与偏好确认方式需要在实现和试用时确定，不把临时状态永久固化。

这套记忆机制是本项目的工程设计方向，口述史与沟通资料为其行为选择提供依据；现有资料并未验证这一架构等同于人的记忆机制或必然改善体验。

### 对话流程与记忆流程

```text
老人发言
  → 语音模块产生最终转写
  → 主控关联用户、会话、轮次，并执行健康／安全分流
  → 一次 prepare_turn 更新短期状态并在预算内读取相关记忆
  → 选取相关个人细节与适用的沟通偏好
  → 主控结合当前反馈、对话规则与来源流式生成回复
  → 语音模块按完整短语合成与播报
  → 根据本轮反馈更新短期状态，必要时立即换题或停止

后台，在允许保存与分析的范围内
  → 会后提取并提交最小必要记录；清理原文缓冲
  → 新增记录、更正或有效期变化，触发受影响的任务
  → 并行：经历与时间线整理／偏好与反例分析／检索准备
  → 分别校验来源与权限，发布可用的新版本
  → 后续轮次读取已完成的结果；分析慢或失败不拖住回复
```

具体时序需联调确定。主控统一决定对老人说什么；本模块提供记忆结果和可复用的对话规则，不另外抢占一条发话通道。

并行执行需服从实时响应：共享 GPU 时后台模型请求初值为 1，轻量索引、缓存与 I/O 可重叠运行，增加模型并发须压测。停止、换题、不保存、更正与删除仍立即处理；相关任务与旧缓存失效不能等后台分析结束。具体任务依赖、来源版本和资源约定见设计稿第 3 节。

### 记忆能力的最小范围

新增的两项能力同样采用渐进方式：子能力先覆盖六类实际交流情境，年谱先支持年粒度与事件前后关系。复杂历法换算保留原话，待有可靠组件后扩展。

| 能力 | 预期行为 |
|---|---|
| 记录 | 只处理适合保存且获准的最终发言，不把中间转写或模型推测当成事实 |
| 短期管理 | 保存当前话题、近期事项与临时交流条件，区分当次状态和跨会话延续信息，支持过期与清理 |
| 持久保存 | 按用户隔离，关联会话与轮次，防止同一事件重试时重复写入 |
| 后台提取与并行分析 | 按数据变化整理经历、观察与偏好，提前准备检索；保留证据与适用条件，明确偏好与推测分开，允许不更新 |
| 检索 | 返回少量相关且获准使用的个人记忆与沟通偏好及来源；没有结果就明确未命中 |
| 情境子能力 | 按当下需要选择自然讲述、担忧支持、低落支持、记忆／理解支持、敏感经历或无障碍方法；当前意愿可随时覆盖旧建议 |
| 结构化年谱 | 时间线索先保留原话，后台推算年份或范围并记录依据；未知与冲突不强填；AI 整理文字与结构化条目使用同一来源 |
| 更正与删除 | 同步处理原始记忆、派生总结、偏好及短期上下文；删除或访问限制需实际生效后再反馈 |

首轮建议用简单存储与固定示例打通这些行为，再根据检索质量决定是否加入语义检索或向量数据库。技术选择服务于跨会话可用、来源可靠与权限生效，不预先绑定某种模型或服务形式。

年谱的特点是**老人自然讲，系统逐步整理**。例如“1950 年出生，二十周岁时进厂，整三年后调车间”，在生日与事件月日未知时，先形成“1970—1971 年间进厂、1973—1974 年间调车间”的推算；不能把范围润色成一个确定年份。相关人物、旧物件和本人认为重要的细节一并保留，AI 不补心理独白或人生评价。详见年谱设计。

### 输入与输出需要表达什么

- **输入：**稳定用户标识、会话与轮次标识、最终转写、当前主题、实际有效的保存／使用许可，以及可获得的交流条件、系统回复方式和用户反馈。谁产生、谁保存这些信息需要与主控约定；缺失的观察不能猜测补齐。
- **记忆输出：**相关经历与细节、短期状态、适用的沟通偏好及其证据；附带来源、时间／有效范围、不确定性、确认与用途状态，以及成功、未命中或失败结果。
- **对话规则：**何时追问、缩小问题、换题或结束，如何引用已有记忆。这些规则交由主控执行，不能只依赖记忆数据库保证。

同一用户的跨会话关联需要稳定用户标识，不能仅凭 `session_id`。家属补充与老人自述应分别标记；检索失败不能返回貌似真实的替代经历。

| 对接方 | 本部分提供什么 | 需要对方提供／确认什么 |
|---|---|---|
| 任务一：语音与当前对话入口 | 关怀式对话规则、相关个人细节及适用的节奏／语言偏好 | 最终转写、轮次信息、可观测的暂停与打断状态、实际语音设置及可调能力；不要求凭空推断情绪 |
| 主控／集成协调人 | 长短期状态、记忆结果、沟通偏好与依据、错误结果约定 | 用户身份、权限状态、实际回复及反馈、会话结束事件、交互繁忙状态、超时处理及唯一回复出口；不等待后台任务完成才发话 |
| 任务二：健康探针 | 保持来源信息，避免将风险标签改写为确诊事实 | 健康／安全分流优先级；哪些结果可保存、如何标记 |
| 家属摘要模块 | 在明确许可下可供摘要使用的记忆 | 可见范围、读取或推送方式、撤回与限制访问的执行方式 |

任务二的现有文档输入是 `session_id / turn_id / text / is_final` 四字段。给记忆模块增加用户或权限信息时，应由主控适配，不能直接把扩展事件原样发给任务二。

本部分不承担 ASR、TTS、独立健康诊断或家属消息发送的实现。对话策略需要和现有主控共同落地；“不保存”“不分享”必须贯穿主控、记忆和下游摘要，不能仅靠一句提示词承诺。

## 7. 怎么判断这部分做好了

功能与对话体验需要同时检查。首轮至少走查以下场景：

| 场景 | 可观察的通过条件 |
|---|---|
| 两次会话谈到同一门手艺 | 第二次能取回获准保存的经历与来源；重启后仍可取回 |
| 年份含糊或语音识别不确定 | 不补造精确年份或人名，不确定性保留 |
| 拒绝某个话题或说累了 | 停止追问，不为完成故事而延长谈话 |
| 允许保存但不准告诉家属 | 记忆与家属摘要按不同用途处理，实际下游调用不泄露该段内容 |
| 无匹配、工具失败或别的用户查询 | 不伪造成功，不返回其他用户的个人记忆 |
| 同一轮重试、后续更正或删除 | 不重复写入；更正／删除后的检索反映实际结果 |
| 长期偏好经常使用 | 能进入当前上下文，同时保留长期来源；不会因退出会话丢失 |
| 今天疲倦或一次沉默 | 只作有条件的当次记录，不直接变成永久偏好或确定情绪标签 |
| 多次要求问题简短 | 总结可追溯到具体反馈，后续主控实际调整问法；对方改变要求时可更新 |
| 删除一条反馈或更正偏好 | 相应派生判断被撤回或重新评估，短期上下文不继续沿用旧结果 |
| 后台故事分析缓慢，老人继续聊天 | 仍读取已发布的有效记忆回复；后台并行不拖慢前台，失败与过载可查询 |
| 只说年龄／相对时间，没有明确年份 | 能保留时间关系并给有依据的范围；不反复追问年份，不自动选周岁或虚岁 |
| 更正出生年或限制某项证据分享 | 相关推算和年谱文字一起失效；家属不能通过派生年份获得被限制的线索 |
| 下次谈到近期关心的小事 | 在相关且获准的情况下自然接续，不为展示记忆而反复提起无关细节 |

评估时检查回复、工具调用和存储结果，不能只看模型是否口头答应。对“有人情味”的判断也要听长者自己的反馈，不把聊天时长或故事数量当作唯一成功指标。
