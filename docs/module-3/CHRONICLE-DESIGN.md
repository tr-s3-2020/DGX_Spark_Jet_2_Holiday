# 结构化人生年谱：时间推理与叙事设计（v0.5）

负责人：卢易锋｜2026-09-26｜状态：设计评审，尚无时间推理或年谱服务实现。

目标：从多次自然讲述中，逐步构成有年份／时期、有事件细节、有来源和 AI 整理文字的个人年谱。它可以像传记一样有可读性，空白与不确定性也要真实可见。无需先问清每一年才能留下故事。

## 1. 两个后台子能力

- **`temporal-reasoning`：**提取原时间表达、识别所指事件和人物、建立时间约束，用程序计算可支持的日期或范围，发现冲突并保存推理依据。
- **`chronicle-writing`：**把已发布事件按时间／时期组织，连接有来源的细节，生成标明 AI 整理的叙事，并提供结构化数据与可读版本。

两者从获准保存的记录工作，不阻塞实时回复。前者嵌入 `story_reconcile`，后者是依赖有效时间结果的 `chronicle_build` 任务；它们可与偏好分析独立推进。内容没变化不反复重写整个人生。

## 2. 时间不能只有一个 year 字段

| 原话形态 | 保存与推理 |
|---|---|
| “1974 年调去维修车间” | 记录 1974，精度为年；不补月日。叙述者明确说出的年份仍是其自述，不等于外部核实 |
| “大概 1974 年前后” | 保留“约 1974 年”；没有更多依据，不任意设为前后两年 |
| “二十周岁时进厂” | 联系同一人的出生依据推算年龄区间；未知生日时保留跨年范围 |
| “进厂三年后调过去” | 保存相对关系；确认“进厂”所指事件后推算，基准模糊则结果也模糊 |
| “那时候再过几年……” | 保存顺序及模糊间隔，不把“几年”硬编码为三年 |
| “孩子出生以后”“退休前” | 先保留事件前后关系，锚点未知也能形成局部顺序 |
| “九十年代”“年轻时” | 前者在世纪明确时为 1990—1999；后者保留人生阶段，不指定年龄或年份 |
| “去年” | 使用这次发言的当地日期作锚点；不能使用之后重跑分析时的日期 |
| 农历、虚岁、地方年号 | 保留历法与计龄依据；未经核验的换算不能写成确定公历日期 |

日期表达借鉴 LOC 的 EDTF 对近似、不确定和缺失信息的保留方式；**下面的约束与年龄计算是本项目设计，EDTF 本身不提供这些算法，首版也不宣称标准合规。** [S45](../../research/elder-conversation-oral-history/notes/S45.md)

特别区分：**“事件发生在 1970 或 1971 年”是可能时间范围，“1970 到 1971 年在厂工作”是持续期间。** 数据与页面不能把前者画成一段持续两年的任职。

## 3. 推理流程与可复核规则

```mermaid
flowchart LR
    A[获准保存的原语言片段] --> B[模型提出事件、人物与时间线索]
    B --> C[验证引用及事件关联]
    C --> D[程序计算范围和关系，检查冲突]
    D --> E[发布事件、时间候选与依据]
    E --> F[后台生成有来源的年谱文字]
    F --> G[本人可读年谱或按权限生成的家属视图]
```

1. **分离原话和推算。** 时间线索保留原文、说话者、会话／轮次、事件与人物 ID、语言、记录时间、来源版本。模型只提出语义候选，不能把算出的年份改写成老人原话。
2. **先核对锚点。** “那年”“他二十岁”有多种指代时保留候选，不默认指最近的事件或老人本人。家属的经历不能合并进老人的事件。
3. **确定规则由程序计算。** 已知公历出生年 B、周岁 A，且事件发生在 A 周岁期间，年粒度的保守包络为 `[B+A, B+A+1]`。这是可能年份，不是连续活动时长；如果明确说“满 A 周岁生日当天／那一年”，并且锚点足够，才可以缩小。
4. **计龄不明时声明假设。** “二十岁”没有说明周岁或虚岁，先保留年龄关系；可给出“按周岁试算”的暂定候选，但不能显示为已确认。虚岁受历法和日期影响，不能统一减一岁。不为此专门插入必答问题。
5. **传播不确定性。** 明确相隔 N 个完整年时，可对锚点区间整体平移；“大概三年”保留近似性。不能通过连续相加让模糊锚点越来越精确。人生常识、常见入学或退休年龄不能充当个人事实。
6. **合并兼容约束，展示矛盾。** 同一事件不同独立证据可缩小交集；交集为空时保留双方为冲突候选，不平均出一个年份，不默默选择新说法。本人明确“刚才说错了”的更正可撤销旧依据。对同一来源的多份 AI 摘要只算一份证据。
7. **有限推理。** 仅处理受影响的事件关联分量；设置遍历数量和时间预算。正向时间关系形成不可能循环、来源缺失或同名人物未分清时停止计算并列入待核实，不让模型无限补全。
8. **失效传播。** 更正出生年时，所有依赖它的推算先失效再重算；删除或限制一个来源时，相关日期、年谱句子和缓存都停止使用。不得从旧年谱文本再提取一次，将被删除的内容写回。

首版只保证年粒度与明确的事件前后关系；月日可原样保留。农历、特殊年号、复杂生日边界和跨历法换算先标为待核实，后续有验证过的日历组件再扩展。

## 4. 核心数据结构

个人事件仍使用 entries 中的 story／detail，新增与其关联的结构化表；不把年谱另建为无法撤回的第二份个人数据库。

| 对象 | 关键字段与语义 |
|---|---|
| `life_events` | `event_id, user_id, entry_id, subject_refs, title, detail_refs, version`；人物和细节分别引用已有来源 |
| `time_assertions` | `assertion_id, event_id, relation, raw_text, evidence_ref, source_version, anchor_event_id, year_value, age_value, age_basis, offset_years, calendar, reported_at`；无值用 null，不补猜 |
| `time_resolutions` | `event_id, alternatives, state, version`；state 为 resolved／tentative／unresolved／conflicted。resolved 仅表示约束可解，不表示外部证实 |
| 时间候选 `alternative` | `kind, display, earliest_year, latest_year, approximate, basis, assertion_refs, assumption_notes, derivation`；kind 为 year／possible_window／relative／life_stage／unknown。未能建立数值边界时两个 year 可为 null；明确持续期间另存 start／end，不复用 possible_window |
| `derivation` | `rule_id, input_refs, input_versions, expression`；描述可复核运算，不保存模型隐藏思维或虚构概率 |
| `chronicle_views` | 用户、用途、政策版本、来源记忆版本、生成状态及条目；每个 AI 整理句子关联支持它的事件／证据／时间版本 |

relation 首版支持 `in_year / at_age / years_after / before_event / after_event / not_before_event / life_stage / unresolved`；持续期间作为独立的开始／结束断言，不把一个入职时点当作整段任职。“车间工作期间收到扳手”可先保存为“不早于调入车间”的弱约束，并保留完整原话，不猜何时离职。age_basis 为 `completed_years / nominal_years / unknown`，calendar 为 `gregorian / lunar / unknown`，不从中文语言标签推定计龄或历法。reported_at 使用原发言有依据的日期及当地时区；旧材料时间未知时不使用处理日期替代。

时间结论的 `basis` 为 reported／derived；事实记录的 self_report／family_report／inferred 仍沿用现有 API，两者不能混淆。确认范围也要明确：确认故事发生过，不等于确认系统推算的年份。

## 5. 年谱怎样呈现

本人版默认分为：有年份的事件、只有时期／相对顺序的事件、需要核实的冲突。多个事件同年而先后未知时并列，不能用排序制造发生顺序。重叠的可能时间范围不强排先后；阅读顺序不是历史断言。空白年份不插入虚构人生事件，也不要求逐年填满。

**虚构演示：**讲述者先说出生于 1950 年，二十周岁时进厂，三年后调去维修车间，并记得师傅送过一把旧扳手。

| 年份／时期 | 年谱条目 | 依据与状态 |
|---|---|---|
| 1950 年 | 出生 | 本人明确自述；非外部核实 |
| 1970—1971 年间 | 进入工厂 | 根据出生年与“二十周岁时”推算；不是任职持续两年 |
| 1973—1974 年间 | 调去维修车间 | 按“进厂三年后”推算，继承锚点范围 |
| 在维修车间期间，年份未详 | 师傅送给他一把旧扳手 | 保留事件关系和具体物件，不补赠送日期 |

AI 整理文字可以是：“据他的讲述，他在二十周岁时进入工厂，三年后调去维修车间。他还记得，在那里工作期间，师傅送过他一把旧扳手。”下方标注“AI 据本人讲述整理”，每句可展开来源。不能添加“从此找到一生的使命”等未说出的评价；不用《史记》的文学感换取虚构心理或戏剧化细节。

结构化视图为 JSON，可读视图为 Markdown／页面；两者读取同一事件与时间数据。首版不增加 PDF 生成或自动发布。示例数据与边界案例见 [chronicle-examples.json](chronicle-examples.json)，均为虚构。

## 6. 什么时候可以轻轻确认

后台可以形成待核实事项，但默认不要求老人回答。只有对当前故事理解有影响、本人愿意核对年谱，或对方自然提起相关线索时，主控才考虑一个简短问题。

例如：“听起来是进厂之后的事，我们先这样记着，可以吗？”若未回应不算确认。不要把推算值塞进问题引导认同，例如“就是 1973 年对吧？”；不反复提醒待补年份，不展示催促式完整度分数。

时间核实在普通陪伴对话中默认关闭主动提醒；在本人主动开启的年谱复核中一次只谈一项，可以跳过，拒绝后当前会话不再重问该项。焦虑、疲劳、低落等支持需要优先于日期核实。

## 7. 权限、接口与协同

- 故事、时间约束、推算和本人年谱沿用 long_term_memory；情境分析沿用 profile_learning。不得从未获准保存的谈话里“只留一个年份”绕过限制。
- 家属版必须先选出可分享的事件及**推理所依赖的全部证据**，再生成摘要。若出生年不允许分享，不能在家属版给出依赖该年推算的日期；可以保留获准的“二十周岁时”，不得以附注泄漏隐藏锚点。图表、标题和 AI 摘要同样检查。
- 更正或删除后，过期视图立即不可读，异步再生成。不能因新版本还没准备好就返回含已撤回内容的旧版；调用方已导出的副本不在本服务追回能力内。
- 读取接口 `get_chronicle` 返回已发布视图，不在线调用模型；`review_chronicle_event` 保存本人复核并触发受影响的后台重算。具体字段见 [API.md](API.md)。
- 任务一提供原语言转写、原发言时刻与可靠轮次引用；主控保留不保存／拒绝要求并只在适当时机复核；第三项负责时间约束、版本、引用和年谱；家属模块按用途读取，不能直接扫库。

## 8. 待实现后的验收

出生年＋周岁跨年、计龄方式未知、多步相对时间、无锚点、约数、指代不清、两个人物、冲突与明确更正、删除锚点、部分分享、月份精度不足、旧录音里的“去年”、故事重复、同年未知先后，都需要可观察验证。数字运算用确定性用例验证，语义提取另测；模型给出正确 JSON 不等于推理正确。

体验验收必须包括：一段完全没说年份的故事仍能保存并正常接话；年谱整理不开启额外实时模型请求；等待的时间项不催促老人；结构化数据、页面与 AI 文字的确定程度一致。比赛演示先展示一段逐步成谱、可更正的故事，不承诺一次访谈写出完整人生。
